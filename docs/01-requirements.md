# 01. 요구사항 정리

## 1. 배경 / 문제

계산기, 단위 변환, 이자 계산, 대출 한도 같은 기능을 쓰려고 매번 다른 사이트를 검색해서 들어간다.
사이트마다 광고가 많고, 계산 결과를 신뢰하기 어렵고, 즐겨찾기 해두기도 번거롭다.

→ **필요한 도구를 한 페이지에 모아 NAS에 띄워두고, 집·모바일에서 언제든 꺼내 쓰는 개인용 도구 모음.**

## 2. 목표

1. 일상에서 자주 쓰는 계산·변환 도구를 한 사이트에서 제공한다.
2. 도구를 카테고리로 분류해 눈으로 훑어 찾을 수 있게 한다.
3. 검색으로 도구를 즉시 찾아 바로 쓸 수 있게 한다.
4. 새 도구를 나중에 계속 추가할 수 있는 구조를 만든다. (추가 비용이 낮아야 함)
5. NAS의 Docker 컨테이너 하나로 운영한다.

## 3. 비목표 (이번 범위 밖)

- 회원가입 / 로그인 / 계정별 데이터 동기화
- 서버 사이드 렌더링(SSR), SEO 최적화
- 다국어 지원 (구조만 열어두고 한국어만 제공)
- 계산 이력의 서버 저장 (브라우저 localStorage까지만)
- 외부 사용자 공개 및 광고 수익화

## 4. 사용자 시나리오

| #   | 시나리오                                | 기대 동작                                                         |
| --- | --------------------------------------- | ----------------------------------------------------------------- |
| S1  | 홈에 들어와 어떤 도구가 있는지 둘러본다 | 카테고리 카드 + 각 카테고리의 도구 목록이 한눈에 보인다           |
| S2  | "계산기"를 눌러 계산기를 쓴다           | `/tools/calculator` 로 이동, 즉시 입력 가능                       |
| S3  | 대출 이자가 궁금해 "대출"을 검색한다    | 검색 결과에 대출 상환·대출 한도 도구가 뜨고, Enter로 첫 결과 진입 |
| S4  | 자주 쓰는 도구를 고정한다               | 도구 카드/헤더의 ★ 클릭 → 홈 상단 "즐겨찾기" 섹션에 표시          |
| S5  | 모바일에서 급하게 단위를 변환한다       | 모바일 레이아웃에서 하단 탭/검색으로 3탭 내 도달                  |
| S6  | 계산 결과를 다른 사람에게 보낸다        | 입력값이 URL 쿼리에 반영 → 링크 공유 시 같은 결과 재현            |
| S7  | 내가 새 도구를 추가한다                 | 도구 폴더 하나 추가 + 메타데이터 작성 → 자동 등록                 |

## 5. 기능 요구사항

### 5.1 공통 셸 (Shell)

- **F-01** 헤더: 로고(홈 이동), 검색 트리거, 다크/라이트 토글
- **F-02** 사이드바(데스크톱): 카테고리 트리, 현재 도구 하이라이트. 모바일은 드로어
- **F-03** 명령 팔레트 검색: `Ctrl+K` / `Cmd+K` / `/` 로 오픈, 방향키 이동, Enter 진입, Esc 닫기
- **F-04** 즐겨찾기: 도구 단위 토글, localStorage 저장, 홈 최상단 노출
- **F-05** 최근 사용: 최근 진입한 도구 최대 8개 저장·노출
- **F-06** 브레드크럼: `홈 > 카테고리 > 도구명`
- **F-07** 404 페이지: 없는 도구 경로 진입 시 검색 유도
- **F-08** 테마: 시스템 설정 따라가기 + 수동 고정, localStorage 저장

### 5.2 검색

- **F-10** 검색 대상: 도구 이름, 설명, 키워드 배열, 카테고리 이름
- **F-11** 오타 허용 퍼지 매칭 (Fuse.js)
- **F-12** 한글 초성 검색 (`ㄷㅊ` → 대출한도, `ㄱㅅㄱ` → 계산기)
- **F-13** 영문 별칭 검색 (`bmi`, `loan`, `unit`)
- **F-14** 결과 없을 때 유사 카테고리 추천

### 5.3 도구 페이지 공통 규격

- **F-20** 상단: 도구명, 한 줄 설명, 즐겨찾기 토글
- **F-21** 입력 즉시 계산 (실시간 반영, 별도 "계산" 버튼은 선택)
- **F-22** 결과 영역: 핵심 숫자 강조 + 보조 지표 + (해당 시) 표/차트
- **F-23** 결과 복사 버튼 (클립보드)
- **F-24** 입력값 URL 쿼리 동기화 (`?principal=100000000&rate=4.5`)
- **F-25** 입력 검증: 범위 초과·문자 입력 시 인라인 에러, 계산은 막지 않고 안내
- **F-26** 계산 근거/공식 접이식 설명 (신뢰성 확보)
- **F-27** "관련 도구" 링크
- **F-28** 빠른 선택 버튼 (자주 쓰는 값을 한 번에 입력)

### 5.3.1 빠른 선택 버튼 규격 (F-28)

숫자 입력은 모바일에서 특히 번거롭다. 3억을 넣으려고 0을 여덟 번 세는 대신,
자주 쓰는 값을 칩 버튼으로 눌러 넣을 수 있어야 한다.

값의 성격에 따라 동작이 다르다. **이 구분을 지키지 않으면 사용자가 결과를 오해한다.**

| 모드  | 동작               | 쓰는 곳                     | 예                                  |
| ----- | ------------------ | --------------------------- | ----------------------------------- |
| `set` | 값을 **치환**      | 몇 가지 중 하나를 고르는 값 | 상환 기간 5·10·20·30·40년           |
| `add` | 현재 값에 **누적** | 조합해서 쌓아 올리는 값     | 대출 금액 +1백만·+1천만·+5천만·+1억 |

- `set` 모드는 현재 값과 일치하는 버튼을 강조하고 `aria-pressed="true"` 를 준다
- `add` 모드는 라벨에 `+` 를 붙여 누적임을 드러내고, **초기화 버튼을 함께 제공**한다
  (누적만 가능하면 값을 줄일 수 없어 막힌다)
- 버튼으로 넣은 값도 직접 입력과 동일한 상한·하한이 적용되어야 한다
  (입력 경로에 따라 결과가 달라지면 안 된다)
- 구현: `components/ui/QuickPicks.vue`

### 5.4 확장성

- **F-30** 도구 = 폴더 1개 (`meta.ts` + `View.vue` + `logic.ts` + `logic.spec.ts`)
- **F-31** `import.meta.glob` 기반 자동 등록 (라우트·검색·카테고리 색인 동시 반영)
- **F-32** 도구 코드 스플리팅 (도구별 lazy chunk)
- **F-33** 도구 비활성화 플래그 (`enabled: false` 로 코드 삭제 없이 숨김)
- **F-34** 카테고리 정의는 한 파일에서 관리

## 6. 비기능 요구사항

| 구분     | 요구사항                                                                                |
| -------- | --------------------------------------------------------------------------------------- |
| 성능     | 초기 JS 번들 < 200KB(gzip), 도구 진입 추가 로드 < 50KB, 홈 LCP < 1.5s (NAS 로컬망)      |
| 반응형   | 360px ~ 2560px. 모바일 우선 설계                                                        |
| 접근성   | 키보드만으로 전체 조작 가능, 폼 라벨 연결, 대비비 4.5:1 이상                            |
| 오프라인 | 정적 자산 서비스워커 캐싱(PWA), 외부 API 없는 도구는 오프라인 동작                      |
| 정확성   | 금액 계산은 부동소수 오차 방지 (정수 원 단위 또는 decimal 처리), 로직은 단위테스트 필수 |
| 보안     | 입력값 외부 전송 없음. 외부 API 사용 도구는 문서에 명시                                 |
| 운영     | 이미지 크기 < 60MB, 컨테이너 메모리 < 64MB, 재시작 자동 복구                            |
| 브라우저 | 최신 Chrome / Safari / Edge / Firefox (ES2020 타깃)                                     |

## 7. 데이터 / 외부 의존

| 항목                         | 처리                                                                  |
| ---------------------------- | --------------------------------------------------------------------- |
| 즐겨찾기·최근사용·테마       | localStorage (`toolbox.favorites`, `toolbox.recent`, `toolbox.theme`) |
| 단위 변환 계수               | 코드 내 상수 테이블 (외부 의존 없음)                                  |
| 세율·대출 규제 비율(DSR/LTV) | 코드 내 상수 + "기준일자" 표기, 변경 시 값만 수정                     |
| 환율                         | 외부 공개 API 호출 (선택 기능). 실패 시 수동 환율 입력으로 폴백       |

> 환율 외에 네트워크가 필요한 도구는 만들지 않는다. NAS가 외부망과 끊겨도 나머지 도구는 정상 동작해야 한다.

## 8. 열린 질문

- [ ] 세금·대출 관련 도구에 "참고용, 법적 효력 없음" 고지를 어디까지 넣을지
- [ ] 환율 API를 붙일지 (붙이면 API 키 관리 필요 → 경량 백엔드 or 빌드타임 주입)
- [ ] NAS 외부 공개 여부 (공개하면 HTTPS·기본 인증 검토)
